# Tools in English, German and Dutch, following autodarts' language

**Date:** 2026-10-01
**Status:** designed with the user section by section on 2026-10-01. The approach, the feature-name rule, the Discord language and all six sections below were approved in conversation. This written spec awaits their review; the implementation plan is written from it.

## The request

> I want you to build i18n into this extension for every feature which will support English (default), Deutsch and Nederlands
>
> I don't know if it's somehow possible to get the information users selected default on autodarts website because users can switch lang at https://play.autodarts.com/settings/general so please check if getting this from login / session data or localstorage please before implementing
>
> also at https://play.autodarts.com/settings/general implement a note that this will also change the lang in Tools for Autodarts and its features
>
> once implemented, remember somewhere that everything new (new features etc) will get translated as well

**Success looks like:**

- Switching the language on autodarts switches every text Tools shows, at once, in that tab.
- German and Dutch are complete, and a check fails the moment one of them is missing a text.
- `/settings/general` says that its Language setting changes Tools too.
- The rule that new work ships in all three languages sits where every session and every contributor reads it.

## What was found

### Where autodarts keeps the language

This was read from the site's own code on 2026-10-01: its i18n chunk, the `useDisplayLanguage` hook, the general settings page and the user menu in the app shell. Chunk names change with every deploy, so look for the behaviour below rather than the file names.

- **Not in the login, the session or the account.** `/settings/general` saves its two switches (seasonal effects, animations) to the account through `updateSettings`. The language picker never calls it.
- **The key is `localStorage["autodarts.settings.language"]`.** It holds `en`, `de` or `nl`, and choosing *System* removes it. On the web, the site's storage wrapper is a cache over plain `localStorage`. The native app swaps in a backend of its own.
- **Start-up.** i18next starts with `lng: Q(stored)`.
  - `Q(v)` takes `v?.split("-")[0].toLowerCase()` if that is `en`, `de` or `nl`, and `undefined` otherwise.
  - With `undefined`, the detector's only source is `navigator`. No `supportedLngs` is set, so it takes the first entry of `navigator.languages`.
  - A first language the site has no text for (`fr-FR`) therefore shows English, even when a supported one comes second.
  - The user menu's "Detected" line works the same thing out from `navigator.languages?.[0] ?? navigator.language ?? "en"`.
- **There are two pickers, and both work live.** Both call the same `setValue`, which writes or removes the key synchronously and then calls `i18n.changeLanguage()`. There is no reload.
  1. The Language select on `/settings/general`: a `<Select>` whose trigger has `id="settings-language"`, inside a vertical `[data-slot="field"]` whose label has `for="settings-language"`.
  2. The language item in the user menu, on every page: a Select while the sidebar is expanded, and a transparent native `<select>` while it is collapsed.
- **Other tabs do not follow.** The wrapper updates its cache on a `storage` event, but nothing calls `changeLanguage` there. Another tab shows the new language on its next load.
- **`<html lang>` stays `en`.** It is static in `index.html` and never updated, so it is no use as a signal.
- **Debug mode.** `sessionStorage["autodarts.i18n.debug"] = "true"` puts the site into i18next's `cimode`, and every label renders as its key. It is per tab.
- **Tone.** The site's German says *du*, lower-case in the middle of a sentence in most strings, and its Dutch says *je*. Neither uses *Sie* or *u*.
- **Descriptions.** The settings page writes them as short phrases without a full stop ("Play animations during gameplay").

### What the extension has to translate

- **No mirror is needed.**
  - Every content script runs on `play.autodarts.com` only (`utils/content-script-matches.ts`), so each one can read the key itself.
  - The service worker shows no text. Its one string, "Download not found", is a relay error.
  - So nothing needs mirroring into extension storage.
- **Text comes from two kinds of code.**
  - 11 Vue apps: the settings overlay, Migration, Auto Start, Saved Players, the QR overlay, the Add Team drawer, External Boards, the Teams pill, Streaming Mode, Animations and Quick Correction.
  - Plain TS modules that write into the site's DOM:
    - Teams' lobby rows and match chips
    - the takeout panel
    - the fullscreen button
    - Discord's button and announcement
    - the audio-unlock notices of the Caller and Sound FX
    - the Quiet Own Darts row
- **Size.** About 600 texts and attributes in templates (~3,800 words), plus about 500 strings in scripts. That is roughly 1,000 to 1,200 strings and ~7,000 English words.
- **No date or number** is formatted per locale anywhere today.

## Decisions taken with the user

1. **Feature names follow the site's pattern.** The site keeps the names that work as names (Caller, Lens, Autoscoring) and translates the descriptive ones (Sound Effects), and so do we. Every name is listed under *Feature names* for approval.
2. **The Discord announcement is written in the host's language**, and it names the lobby's settings the way the site names them.
3. **Approach A: a small module of our own.** It was weighed against vue-i18n v11, which would have to be installed into each of the 11 apps and reserves `{ } | @` in messages. The browser's `_locales` were also considered, but they follow the browser's language and cannot switch while the extension runs.
4. **Tools gets no language picker of its own.** The site's setting is the only control, and the note on `/settings/general` says so.
5. **Other tabs switch when they reload**, as the site's do.
6. **Numbers keep their format** (`1.5 s`, `45%`), as the site's scores do.
7. **The note goes on `/settings/general` only**, not on the user menu's language item.
8. **The store listing and the manifest description stay out.** They are a separate job, and they follow the browser.

## 1. Which language Tools shows

`utils/i18n/site-language.ts`:

```ts
export type Language = "en" | "de" | "nl";
export const LANGUAGES: readonly Language[] = [ "en", "de", "nl" ];
export const SITE_LANGUAGE_KEY = "autodarts.settings.language";

/** The site's own normaliser: "de-AT" → "de"; a language we have no text for → undefined. */
export function normaliseLanguage(value: string | null | undefined): Language | undefined;

/** The language the site shows in this tab, worked out by the site's own rule. */
export function readSiteLanguage(storage?: Pick<Storage, "getItem">, nav?: Pick<Navigator, "languages" | "language">): Language;
```

The rule, in order:

1. If the stored value normalises to `en`, `de` or `nl`, use it.
2. If a value is stored, is not `system` and is none of ours, use **English**, our default. This is a language the site added before we did. The site would show it, but we have none of its text.
3. If nothing is stored, or the value is `system`, use `navigator.languages[0]` (or `navigator.language`), normalised, if it is one of ours.
4. Otherwise, use English.

`utils/i18n/index.ts` keeps one reactive `language` per content-script bundle. It is read when the module is first imported.

**Live switching.**
- Capture-phase listeners on `window` for `pointerup`, `click`, `keydown` and `change` read the key again on the next tick, and once more about 250 ms later.
  - Both pickers write the key synchronously inside the event that picks a language.
  - The second read covers a select that commits a frame late.
- If the value differs from the last one seen, `language` changes.
- A `storage` event for the key only records the new value as seen. The tab keeps the language its own site page is showing.
- The listeners are installed once, and only where `window` exists. A module that ends up in the service worker must not touch it.

`onLanguageChange(callback)` returns an unsubscribe function. It is for code that wrote text into the page once.

**Debug mode.** While `sessionStorage["autodarts.i18n.debug"] === "true"`, `t()` returns the key path.
- This is the site's own flag, set per tab, so Tools renders keys alongside the site.
- Any English still on screen in that mode is text that bypasses the catalogs.

## 2. Catalogs, keys and terminology

### Layout

```
locales/
  GLOSSARY.md         the site's words, the names table, tone, how to re-pull the site's tables
  en/index.ts         gathers the files below — English is the source of truth
  en/common.ts        Add, Delete, Cancel, Search, Close, Save, Done, …
  en/settings.ts      header, tabs, Export/Import, advanced panel, dialogs, notifications, What's New, Migration
  en/library.ts       the shared library parts: search, counts, empty and no-result states, Add, ⋯, two-click delete, upload/TTS/sound dialogs, volume
  en/triggers.ts      every trigger's hint line and the pattern lines
  en/gameModes.ts     game modes and their groups, as the site labels them
  en/site.ts          what we draw into the site's own pages (the language note, the Quiet Own Darts row)
  en/<feature>.ts     one per feature: zoom, caller, soundFx, wled, animations, teams, …
  de/…   nl/…         the same files, the same keys
```

- **German and Dutch files are checked against English.** `locales/de/zoom.ts` is `export default { … } satisfies Translation<typeof enZoom>`. It has the same keys, every leaf is a string or a plural, and there are no extras.
- **Keys name the feature first, then the place**: `zoom.name`, `zoom.card`, `zoom.intro`, `zoom.position.title`, `zoom.position.description`, `zoom.position.options.bottom`.

### Message format

- Messages are plain strings with `{name}` placeholders.
- A plural is written `{ one: "{count} sound", other: "{count} sounds" }`, and `new Intl.PluralRules(language)` picks the form.
- Inline `<b>`, `<i>`, `<code>` and `<br>` are allowed.
  - They are parsed into elements and never handed to `innerHTML`.
  - No other tag is recognised, so `<script>`, or a player called `<b>`, stays text.
- A `{slot}` marker holds a link or a component inside a sentence. `<AppTrans>`'s named slot of that name fills it.

## 3. How the code uses it

```ts
// utils/i18n/index.ts
export const language: Readonly<Ref<Language>>;
export function t(key: MessageKey, params?: Record<string, string | number>): string;
export function onLanguageChange(callback: (language: Language) => void): () => void;

// composables/useI18n.ts — auto-imported like useConfig
export function useI18n(): { t: typeof t; language: Readonly<Ref<Language>> };
```

- **`MessageKey`** is the union of the English catalog's key paths, so a typo like `t("zoom.positon.title")` fails the type check.
- **Vue components.**
  - Get `t` with `const { t } = useI18n()`, then write `{{ t("…") }}` or `:title="t('…')"`.
  - Option arrays (`POSITIONS`, `ZOOM_ON`, `VIEWS`) become `computed`.
  - There is no `app.use()` anywhere. `t()` reads the reactive language, so every mounted app re-renders on a switch.
- **`<AppTrans path="…" :params="{…}">`** (`components/AppTrans.vue`, App-prefixed like the other shared parts) renders a message's inline tags as elements and its `{slot}` markers through named slots:

  ```vue
  <AppTrans path="whatsNew.footer"><template #changelog><a :href="CHANGELOG_URL">{{ t("whatsNew.changelog") }}</a></template></AppTrans>
  ```

- **Plain TS that writes into the page** imports `t` and `onLanguageChange` from `@/utils/i18n`.
  - Text a module works out again on every mutation pass needs nothing more. Teams' `if (note.textContent !== text)` is one example.
  - Text built once registers `onLanguageChange(rebuild)` and releases it on the module's existing teardown.
  - Translated text goes in through `textContent` or built nodes, so a player name inside a sentence never becomes markup. The two audio-unlock notices that build `innerHTML` today get their message through `textContent`.
- **Data holds keys, not text.**
  - The feature registry in `PageConfig.vue` stores `nameKey`. The dialog heading is `t("settings.dialogTitle", { feature: t(nameKey) })`, which replaces the string surgery on "… Settings".
  - `utils/trigger-catalog.ts` keeps its tokens. Its descriptions and pattern lines move to `triggers`.
  - `GAME_MODE_GROUPS` keeps its modes and takes its labels from `gameModes`.
  - The Discord announcement names each lobby setting from our catalog, using the site's words copied in through the glossary. A setting it does not know keeps today's humanised key ("Max Rounds").
- **Numbers keep their format.**

The catalogs are about 45 KB of text per language. All three go into each of the five content-script bundles that show text, which are about 5 MB each today. They are pure data, with no side effects for the tree-shaker to keep.

## 4. The note on `/settings/general`

**What it says.** One line, in the language the page is in, written in the style of the site's own descriptions:

| | |
|---|---|
| en | Also changes the language of Tools for Autodarts and its features |
| de | Ändert auch die Sprache von Tools for Autodarts und seinen Funktionen |
| nl | Wijzigt ook de taal van Tools for Autodarts en zijn functies |

**Where it goes.** It goes inside the site's Language field, directly under the select, the way the switches below carry their own descriptions.
- It is a `<p>` that copies the class list of a site field description on the same page, the way Quiet Own Darts clones its row, so it wears whatever classes the site uses this week.
- If no description is there to copy, it falls back to the site's set as of today: `text-muted-foreground text-left text-sm leading-normal font-normal`.

**How it finds the field.**
1. First, `#settings-language`. The site sets that id on the select in its own source, and the field's label points at it.
2. Then, as a fallback, a `[data-slot="field"]` whose `[data-slot="field-label"]` reads "Language", "Sprache" or "Taal". Those are the site's own words.
3. If neither is found, it shows no note. It never guesses a place.

**How it behaves.**
- Mounted from `entrypoints/content/index.ts`, the content script that runs on every page, next to the Quiet Own Darts switch. It has that script's live language, so the note switches along with the page when a language is picked.
- A MutationObserver puts it back if React redraws the field. When the field leaves the screen, the note goes with it. It is marked `data-adt-language-note`.
- The language item in the user menu gets no note. It is a one-line row whose subline ("Deutsch erkannt") leaves no room.

## 6. Checks, testing and the standing rule

### Mechanical checks

- **Types.** German and Dutch files `satisfies` their English twins, and `t()` keys are typed. On its own this is a weak signal, because `yarn compile` already fails with 14 errors on a clean tree. Hence the next two checks.
- **`yarn i18n:check`** is `tsx scripts/i18n-check.ts`, committed. It exits non-zero when:
  1. German or Dutch lacks a key, or has one English doesn't;
  2. a key's `{placeholders}`, `{slots}` or inline tags differ between the languages;
  3. a German or Dutch string is empty, or is identical to English without being on the allowlist (the names that stay, `WLED`, `OK`, game modes the site doesn't translate);
  4. a plural lacks `one` or `other`;
  5. a template still holds bare text with letters in it, using the same `@vue/compiler-sfc` scan that sized this job (symbols such as `·`, `%` and `×` are allowed);
  6. a script assigns a string literal with letters in it to `textContent`, `title`, `placeholder`, `aria-label` or `innerHTML`.
- **ESLint `vue/no-bare-strings-in-template`**, from eslint-plugin-vue (already installed). It is set to `error`, with the same allowlist and our own text-carrying props (`OptionRow` `title`/`description`, `AppAlert` `title`, `AppNumberInput` `label`, …), so the editor marks new hard-coded text as it is typed.

### Tests

- **Pure logic under `tsx` and `node:test`**, run from the scratchpad as for `utils/library-search.ts`:
  - `readSiteLanguage` over stored values and browser lists:
    - `de`, `de-AT`, `nl-BE`, `en`
    - `system`, absent, an empty string and a garbage value
    - a future `fr`, which must give English
    - `fr-FR` followed by `de-DE`, which must give English
  - interpolation and plurals in each language;
  - the inline-tag parser, including that unknown tags and a player called `<b>` stay text;
  - `i18n:check` itself, against a deliberately broken catalog.
- **In the dev Chrome**, in a tab of my own, parked at `about:blank` before every edit:
  - each language set through the site's key and a reload, then screenshots of every tab and every dialog in German and Dutch;
  - overflow at 390 px and on desktop, since German runs about 30% longer;
  - the site's debug flag, where any English left is a missed string;
  - a live switch from both pickers, across the overlay, a lobby and a bot match;
  - the note, which must appear, follow the picker, come back after a redraw, and be absent everywhere else;
  - English screenshots before and after, which must match.
- **Dutch** is written from the site's tables and the glossary, but nobody in the loop is a native speaker. It needs a Dutch user to proofread it before release (see *Open points*). German the user reviews.

### The standing rule

- **CLAUDE.md** gains a "Translations" section next to "README Maintenance":

  > Every text Tools shows goes through `t()` (`useI18n()` in components, `@/utils/i18n` in scripts, `<AppTrans>` for sentences with markup or links). English, German and Dutch land in the same change: the English in `locales/en/<file>.ts`, the others in `locales/de/` and `locales/nl/`. Use the site's own words for its buttons and darts terms (`locales/GLOSSARY.md`), German *du*, Dutch *je*. `yarn i18n:check` must pass. What's New is translated when it is written.

- **A memory entry** records the user's standing preference and the parts that aren't obvious: the glossary, *du*/*je*, and Dutch proofreading.
- **README** gains a short "Languages" section. Tools speaks English, German and Dutch and follows the language set on autodarts, in Settings → General or the user menu, where *System* follows the browser.
- **CHANGELOG** gains an `[Unreleased]` entry.

## Rollout

All of this ships in one release, built in six stages:

1. **Core and the rule:** detection, `t`, plurals, tags, `AppTrans`, `useI18n` and debug mode; the note on `/settings/general`; `i18n:check`, the ESLint rule, the glossary and `site-strings.mjs`; the CLAUDE.md section and the memory entry.
2. **The settings overlay's shell and the shared parts:**
   - the header, tabs, advanced panel, Export/Import and notifications
   - `SettingsModal`, `ConfirmDialog`, What's New and Migration
   - the `App*` controls and the library parts
   - triggers and game modes
3. **Lobbies:** the six panels, plus the lobby scripts (Auto Start, Saved Players, QR, the Teams drawer and rows, Discord's button and announcement).
4. **Matches:** the eighteen panels, plus the match scripts and apps.
5. **Boards, and Sounds & Animations:** External Boards, Animations, the Caller, Sound FX and WLED, the audio-unlock notices, and the Quiet Own Darts row.
6. **The sweep:**
   - debug mode and screenshots in German and Dutch
   - overflow, live switching, and English unchanged
   - README and CHANGELOG

## Risks

- **The site's key or pickers change.** Both are new, from late September. Everything depends on one function and one key name, and a key that disappears reads as *System*, which follows the browser, the same as the site.
- **German runs longer.** Card titles, buttons and segmented controls are where it overflows. They are checked at 390 px and on desktop in stage 6. A text that does not fit gets a shorter wording, not a smaller font.
- **Type cost.** A union of ~1,200 key paths can slow `vue-tsc`. If `yarn compile` gets noticeably slower, `i18n:check` generates a flat `MessageKey` declaration instead of the recursive type.
- **What's New gets translated each release.** The CLAUDE.md rule makes it part of writing the notes.

## Open points for the spec review

1. **Should the release workflow run `yarn i18n:check` before it builds?** Then a release with a missing translation fails in CI. That isn't in the approved sections. It is a one-line step in `.github/workflows/release.yml`, and it is left out unless asked for.
2. **Who proofreads Dutch?** One option is asking a Dutch user, for example in the Discord. The German can be reviewed by the user.
